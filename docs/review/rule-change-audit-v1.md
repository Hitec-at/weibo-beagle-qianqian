# 规则变更独立审计 v1

## 目的

独立审计回答一个有限问题：这次规则新增、修改、暂停或废弃，是否破坏了定义、
证据和历史分类边界。

审计不复算覆盖率，也不使用少量样本自动调阈值。当前微博存量尚未完整，任何
覆盖率或召回率结论都可能失真。

## 两类审计

### 确定性检查

`rule_audit.py` 只读检查：

1. 定义与边界是否完整。
2. 正反例、搜索词和排除条件是否足以支持规则。
3. 修改是否导致原有公开样本明显丢失。
4. 删除或暂停后是否仍存在公开关联和数据库记录。

确定性检查不会执行语义判断，也不会修改 seed、数据库、分类结果或定时任务。

### 独立语义盲审

语义审计子智能体只读取：

- 当前规则定义、边界、排除条件和变更说明。
- 原始微博正文、媒体信息和审核允许使用的评论证据。
- 固定历史样本和确定性检查报告。

子智能体必须先独立判断，再看提案者或候选审核员的结论，避免被原结论锚定。
审计结论必须引用具体微博 ID、评论 ID 或规则字段。

## 四种检查

### 1. 定义与边界

检查名称、来源、解释、判断边界和非启用状态是否清楚。缺少关键文字给
`warn`，不因存量不完整直接 `block`。

### 2. 证据与防止过拟合

检查是否有代表微博、人工审定帖子或可复现的正文样本，是否有排除词等反例线索。
只有一个宽泛搜索词时给 `warn`，不能据此自动公开或调高阈值。

样本不足时输出“不足以评估”，不能补造反例，也不能用一两个样本推出通用结论。

### 3. 历史回归

修改规则时，用新旧规则分别匹配当前数据库，找出修改前公开、修改后不再命中的
样本。明显丢失只给 `warn`，由独立语义盲审确认是合理收紧还是误伤。

当前数据不完整，这一结果不是召回率，也不是最终影响面。

### 4. 删除与暂停残留

从 seed 移除规则后，如果数据库仍有公开关联：

- 规则已明确标为 `paused` 或 `deprecated`：给 `warn`，提醒检查页面可见性。
- 规则没有停用状态但仍有公开关联：给 `block`，先补生命周期处理再发布。

## 审计结论

- `approve`：确定性检查没有 warning 或 block，仍需按风险决定是否做语义盲审。
- `warn`：存在样本不足、定义缺口、单搜索词或可能历史回归，需要人工或独立语义审计。
- `block`：规则身份重复、明显名称冲突或删除后仍公开残留，不能直接发布。

同一模型与同一数据仍可能产生相关性偏差。独立审计降低“先看结论再找理由”的风险，
但不等于绝对客观；高风险规则仍需人工最终批准。

## 命令

```bash
python rule_audit.py \
  --seed memes.seed.toml \
  --previous-seed /path/to/old-seed.toml \
  --database data/weibo.db \
  --output dist/rule-audit/STAMP
```

输出：

- `rule-audit.json`：固定字段，便于机器读取。
- `rule-audit.md`：供审计子智能体和人工阅读。

退出码 `0` 表示 approve 或 warn，`1` 表示 block。

## 工作流

1. 规则维护者提交变更和证据。
2. 系统运行确定性检查。
3. 独立子智能体按本文件做语义盲审。
4. 审计 warning 或 block 进入统一人审。
5. 人工批准后才走 Issue 和 PR。
6. 合入后重新分类并在固定样本上回归。

审计只能生成报告，不得自动修改规则、分类、few-shot、文档或定时任务。
