# 候选审核准则 v1

## 任务

判断一条微博是否应关联到指定 N宗罪条目。只做当前条目的证据判断，不扩展到其他
条目；需要改归其他条目时写入 `proposed_changes`，不要自行接受其他条目。

## 证据顺序

1. 原微博正文。
2. 转发源正文、图片或视频元数据。
3. 评论中的观众命名、解释、关联和情绪。
4. 搜索 query、命中词和排名只用于解释候选来源，本身不是事实证据。

评论不能单独证明钱钱实际做过某事。跨微博短链或评论指代在找到被引用原微博前，
只能作为存疑线索。

## 决定

- `accept`：正文或媒体直接满足条目定义和边界，且没有命中排除条件。
- `reject`：语义不符、只有人物别名、只有观众玩梗、命中排除词、事实属于另一明确
  条目，或证据不足但可以明确排除当前条目。
- `uncertain`：需要更多上下文、原文缺失、短链未展开、所指对象不明确，或证据
  同时符合多个条目的关键部分。

以下情况不得自动接受：

- 只有关键词，没有行为或结果描述。
- 只有称呼，没有具体行为。
- 只说明观众反应或二创解释。
- 内容属于另一个更具体的 N宗罪。
- 原文缺失或只有无法验证的短链。

## 输出

只输出 JSON 决定文件，不修改数据库和代码。每项必须包含：

- `candidate_key`
- `decision`
- `confidence`：0–1
- `reason`：一句话说明依据
- `evidence`：引用原微博字段或具体评论 ID
- `proposed_changes`：无需改归时为空对象

置信度 `>= 0.85` 且证据完整的 `accept/reject` 才会自动处理；其余进入人审汇总。
