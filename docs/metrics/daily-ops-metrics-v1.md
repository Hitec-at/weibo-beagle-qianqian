# 每日数据运营指标口径 v1

更新日期：2026-11-16

本文只定义指标和最小采集口径，不实现仪表盘，也不把指标当作自动调参目标。存量微博尚未抓完时，所有指标只能描述当前样本，不能宣称覆盖全站。

## 设计原则

1. 每个指标只回答一个流程问题，并注明观测阶段。
2. 百分比必须同时报告分子、分母和样本量。
3. 样本不足时报告原始计数或标注“样本不足”，不强行计算比例。
4. 自动化率不能单独代表优化成功，必须和人工推翻率、人工主观评分一起看。
5. 指标用于发现问题和比较版本，不直接作为修改分类边界或阈值的依据。

## 最小指标集

| 编号 | 指标 | 观测阶段 | 核心用途 |
| --- | --- | --- | --- |
| M1 | 运行完整性 | 微博采集、分类、发布 | 判断当天数据是否完整可用 |
| M2 | 候选评论覆盖率 | 评论采集 | 判断评论是否真正服务待审候选 |
| M3 | 规则查询贡献 | 关键词匹配、候选生成 | 判断某个查询词或规则是否有效、是否过宽 |
| M4 | 自动处理率 | 微博候选审核 | 判断人工负担是否真正下降 |
| M5 | 人工推翻率 | 审核结果反馈 | 判断自动审核是否可靠 |
| M6 | 语义建议采纳率 | 评论语义分析 | 判断评论分析是否产生可用建议 |
| M7 | 人工审核评分 | 最终人审反馈 | 记录人对每日产物的主观评价 |

## M1 运行完整性

- 观测阶段：01:00 微博采集、分类、评论采集、证据生成和数据发布。
- 定义：一次计划任务是否生成完整的成功清单。
- 公式：`成功完成次数 / 应执行次数`。
- 数据来源：`dist/daily-ops/*/run-manifest.json` 的 `status`、`failed_stage`、请求账本和未完成资产。
- 报告格式：`成功 X / 应执行 Y`，同时附当天未完成资产数量。
- 用途：识别 Cookie、额度、风控、发布失败和任务中断；没有成功清单的运行不能进入审核。
- 局限：成功只表示流程完成，不表示分类正确，也不表示所有微博和图片都完整。

## M2 候选评论覆盖率

- 观测阶段：评论采集。
- 定义：候选优先选中的微博中，成功获得一级评论首页的比例。
- 公式：`有评论线程的候选优先微博数 / 候选优先选中的微博数`。
- 数据来源：当天 `comment-pilot.json` 的选帖来源和 `comment_threads`。
- 报告格式：`命中 X / 候选选样 Y`，并注明候选池不足导致的探索补位数量。
- 用途：确认“候选优先评论”没有再次与待审候选错开。
- 局限：有评论不等于评论有判断价值；该指标不评价评论内容质量。

## M3 规则查询贡献

- 观测阶段：关键词搜索、baseline 构建和候选生成。
- 定义：每个规则或查询词在当前 baseline 中产生的唯一候选微博数，以及其中进入审核和最终接受的数量。
- 公式：按 `(rule, query)` 分别报告 `唯一候选数`、`已审核数`、`接受数`、`拒绝数`。
- 数据来源：`baseline_candidates`、`candidate_reviews` 和当天 baseline 报告。
- 报告格式：计数表，不默认计算比例。
- 用途：识别从不产生候选的词、主要由泛词产生大量噪声的规则，以及同一规则内不同查询的贡献。
- 局限：当前语料不完整，不能把“没有找到”解释为现实中不存在；只有少量审核结果时不能据此外推精度。

## M4 自动处理率

- 观测阶段：微博候选审核。
- 定义：子智能体结论达到自动处理条件并实际落库的比例。
- 公式：`自动接受或拒绝数 / 已审核候选总数`。
- 数据来源：`candidate_reviews` 中的 `decision`、`human_required`、`applied`。
- 报告格式：`自动处理 X / 已审核 Y`，并拆分接受和拒绝。
- 用途：判断审核流程是否减少低风险重复劳动。
- 局限：自动处理率越高不代表质量越好；必须同时观察 M5 和 M7。

## M5 人工推翻率

- 观测阶段：自动审核结果复核和人审反馈。
- 定义：经过人工再次检查的自动决定中，被人工改成不同最终决定的比例。
- 公式：`人工推翻的自动决定数 / 人工复审过的自动决定数`。
- 数据来源：自动决定及其抽样审计记录、最终人工决定。
- 报告格式：`推翻 X / 复审 Y`；没有复审时写“未观测”，不能记为 0。
- 用途：衡量自动审核的真实可靠性，优先发现语义理解偏差。
- 局限：当前没有对全部自动决定进行人审，因此这是抽样指标，不能外推为全库错误率。

## M6 语义建议采纳率

- 观测阶段：评论语义分析与人审决策。
- 定义：人工已处理的语义建议中，最终被采纳或部分采纳的比例。
- 公式：`采纳或部分采纳的建议数 / 已处理建议数`。
- 数据来源：`semantic-proposals-v1` 建议文件及人工审核结论。
- 报告格式：`采纳 X / 已处理 Y`，并附重复建议数。
- 用途：判断评论分析是否持续产生有效规则、分类或文档改进。
- 局限：建议可能被暂时搁置，未处理项不能计入分母；高质量但重要的建议数量可能很少，比例需要结合具体内容阅读。

## M7 人工审核评分

- 观测阶段：每日统一人审清单交付后。
- 定义：对当天产物的整体可用性给出 1–5 分主观评分，并可选填一句原因。
- 评分标准：
  - 1：不可用，证据或分类结论明显错误。
  - 2：错误较多，需要大量返工。
  - 3：喜忧参半，需要明显修改。
  - 4：基本可用，只需少量修改。
  - 5：可直接决策，证据清楚且没有明显遗漏。
- 公式：`所有人审评分之和 / 评分次数`。
- 数据来源：人工审核记录；当前先手工记录，后续再决定是否入库。
- 报告格式：`平均 X.X 分（N 次）`，同时给出评分分布。
- 用途：捕捉自动化指标无法表达的“是否有用、是否好审、是否可信”。
- 局限：主观评分可能受当天任务量和审核习惯影响，必须结合 M4、M5 和具体错误案例。

## 明确排除的指标

- 不计算整库召回率：存量微博尚未抓完，没有可靠分母。
- 不计算整库精确率：未审核候选不能默认正确或错误。
- 不把候选总数作为单独优化目标：增加候选可能只是增加噪声。
- 不比较模型平均置信度：不同批次和规则不可直接横向比较。
- 不把自动处理率作为唯一成功标准：这可能鼓励审核员草率自动处理。

## 最小采集节奏

- 每次 01:00 任务：M1、M2、M3。
- 每次 03:30 审核：M4、M6，以及可用的 M5 审计样本。
- 人类查看统一人审清单后：M7。

本文只确认口径。是否把 M1–M7 写入完成清单、生成周报或做页面，需另行评估。
