# 项目决策记录

本目录记录影响架构、数据口径、安全边界或产品规则的决策。词汇表解释“是什么”，路线图解释“何时做”，本目录解释“为什么这样做”。

## 什么时候需要记录

- 有多种合理方案，选择会影响后续兼容性、数据质量或运维成本。
- 改变用户可见名称、分类边界或公开展示规则。
- 引入新的数据源、模型、云服务、权限边界或不可逆迁移。
- 已经反复讨论，后续会话容易重新争论的事项。

纯样式微调、一次性的局部实现细节和能够直接从代码看出的普通选择，不需要单独记录。

## 文件与格式

文件名使用 `NNNN-short-title.md`，编号递增。必要字段：

```markdown
# 决策标题

- 状态：提议 / 采用 / 废弃 / 被替代
- 日期：YYYY-MM-DD
- 关联：Issue、PR、词汇表或代码路径

## 背景

需要解决的问题和已知约束。

## 决策

选择了什么，边界是什么。

## 备选方案

考虑过但没有采用的方案及原因。

## 后果

会得到什么、需要承担什么，以及何时应重新评估。
```

被新决策替代时，不删除旧记录；把状态改为“被替代”，并链接到新记录。
