# 规则包预检与生命周期

- 状态：采用
- 日期：2026-11-16
- 关联：Issue #85、`memes.seed.toml`、`memes.py`、`wbq.py`

## 背景

分类规则和 query pack 会持续新增、修改和停用。此前从种子文件删除条目不会
自动改变数据库中的条目状态，历史关联和候选也可能继续被页面或后续审核使用。
同时，规则包缺少统一检查，无法提前发现定义缺失、术语冲突、帖子缺失或把宽泛
单词误作高精度公开规则的问题。

## 决策

1. 规则条目使用 `active`、`paused`、`deprecated` 三种内部状态，默认
   `active`。这些状态是工程状态，不是新的用户可见分类名称。
2. `active` 条目参与页面、分类、搜索 probe、baseline 和候选审核。
   `paused` 和 `deprecated` 条目保留元数据、历史关联和审核记录，但不参与
   上述公开或自动流程。
3. 种子中消失的条目自动标为 `deprecated`，不物理删除，也不删除历史关联。
4. `memes-preflight` 只读检查规则包，输出 error 和 warning。缺失边界、
   无搜索词、无反例或只有单个自动公开词等问题先警告；定义冲突、无效字段和
   引用不存在正例帖子等明确错误阻止导入。
5. 不设置固定的最少词数。存量语料尚未完整时，宽泛或证据不足的规则只能作为
   候选规则，不能因为样本偶然通过就自动公开。

## 备选方案

- 删除种子时直接物理删除数据库条目：会让历史审核和回滚失去依据，不采用。
- 所有预检问题都阻止导入：在语料和规则持续补全阶段过于僵硬，不采用。
- 为“宽泛词”建立固定词数门槛：容易过拟合当前小样本，不采用。

## 后果

停用规则不会静默消失，页面和自动流程会先停止使用，历史证据仍可审计。
运营者需要在规则变更前执行预检，并根据警告补充边界、正反例和搜索词。
如果后续语料足以支持更严格的发布门槛，可新增独立决策，而不是修改本记录。
